### 1. BLOCKER: the official CSV does not save
Steps: new Case → Upload CSV the files `GEMINI_Heating_Demand_Daily_2027.csv` and `GEMINI_Cooling_Demand_Daily_2027.csv` → connect to Heating and Cooling → Save version.
Result: button disabled, message "first column = 'date'; expected 'time'". Renaming the column to `time` also gives an error: "has no offset; expected ISO 8601 with an offset or Z" (730 error lines). Only the format `2027-01-01T00:00:00Z` is accepted.
Expected: the official file is accepted directly (a plain date and a `date` column are accepted or converted automatically).

### 2. HIGH: the uploaded file does not connect to the field
Steps: in the demand field, Upload CSV.
Result: the file is saved (the Files count and the case version go up) but the field goes back to an empty "constant". You must click "∿ series" again and pick the file, column and unit by hand.

### 3. HIGH: plant Depth
Steps: Plant → Plant → Depth = 2500 → Save.
Result: the dropdown has no unit; raw 422: "depth = 2500.0; expected a Quantity or {'value', 'unit'}… accepted units: ft, in, km, m, mm". The same field on the Doublet module has a unit and saves.

### 4. HIGH: Restore in History
Steps: in an imported copy of SPE, Plant History → Restore v1 "Official candidate" → Run the design.
Result: "study_failed: schedule: params.control.dispatch is missing; expected 'least_cost'". The restored version has lost control (dispatch/outages), backup, depth, size and type. Setting Dispatch on the Doublet does not help.

### 5. HIGH: Study with 100 missing parameters
Steps: template "Heating Absorption Cooling Plant" + full Case → the Plant page shows only "1 value missing" (fluid density) → fill it → new Study "Run the design".
Result: blocked with 100 missing parameters (pipes, ESP, well sections, exchanger, boiler capacity…). `d0.reservoir.permeability` and `aquifer_thickness` are reported as missing even though they are filled in the Case and the form says "empty takes it from the case".
Expected: the Plant page shows the same gaps as the Study, and the Case values are inherited.

### 6. HIGH (data): the "SPE GeoHackathon 2026" project
The current plant v3 "Started from template ATESPlant" (Administrator, 2 November 23:21) is empty, has 6 errors ("requirements[..].on = 'doublet': the plant has no unit of that role") and Study/Results is "Out of date". Restore to v1 also hits bug 4. It must be fixed before the competition.

## Main competition flow with agents: "Design a plant from these files at the lowest cost"
**BLOCKER.** All 6 approvals were given. Run 7 minutes, 162 steps, 19 errors. At the end nothing was saved: no plant, no study, and the case also stayed unchanged. Final text: "No design passed gemini's checks… The last design None (None) failed verification_missing". The run status is "done", not "failed".
Run log on the Dell: `~/qa-geomind-2026-11-03/downloads/run_ef96.json`

Causes from the log:
1. All 4 `build_plant` calls were sent with `"plant": {}` and the backend gave the misleading message "old_format: this file has an older shape". The large tool argument did not reach the backend.
2. Each template has 130 to 136 missing parameters. The designer spent the 29-step budget of each round reading them one by one with read_stored (many with an `unknown_name` error) and stopped after round 2.
3. `set_case` with the official files was rejected again because of date/time.
4. `read_document` drops the first character of the file (returns "ate,heating…").

Main root causes: large tool arguments (365 values or a full plant) get lost or stuck, and each template has about 130 missing parameters.
